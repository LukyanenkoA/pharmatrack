# PharmaTrack — сериализация упаковок лекарств на Ethereum (ERC-721)

**Демо-сайт:** <https://lukyanenkoa.github.io/pharmatrack/> ·
**Репозиторий:** <https://github.com/LukyanenkoA/pharmatrack>

Учебный проект по курсу «Блокчейн»: противодействие поддельным лекарственным
препаратам через учёт **каждой отдельной упаковки** в блокчейне и QR-верификацию
покупателем.

**Проблема.** По данным ВОЗ, около 1 из 10 медицинских продуктов в странах с
низким и средним уровнем дохода — некачественные или поддельные. Цепочка
поставок непрозрачна: покупатель не может проверить происхождение коробки.

**Решение.** Производитель регистрирует партию и выпускает **по токену
(упрощённый ERC-721) на каждую коробку**: у коробки свой `tokenId`, свой
QR-секрет (в блокчейне — только `keccak256`-хэш) и свой QR-код. Партия едет по
цепочке «производитель → дистрибьютор → аптека». Аптека при продаже необратимо
помечает коробку `markSold(tokenId)` — контракт навсегда запоминает `soldAt`
(`block.timestamp`).

**Детектор подделки.** Покупатель сканирует QR и **бесплатно** (`verifyView`,
без кошелька и ETH) видит:

- кода нет в реестре → **ПОДДЕЛКА**;
- коробка «новая», но её `tokenId` уже продан `soldAt` → **КОПИЯ**
  (уникальный токен + статус Sold + дата продажи — счётчик сканирований не нужен);
- партия отозвана → **не покупать**;
- `Active`, в аптеке, срок не истёк → **ПОДЛИННАЯ**.

Схема повторяет промышленную сериализацию (EU Falsified Medicines Directive:
уникальный идентификатор упаковки + «декомиссия» при продаже).

## Технологии

| Слой | Технология | Назначение |
|---|---|---|
| Смарт-контракт | Solidity ^0.8.24 (solc 0.8.39, evmVersion paris) | Реестр партий и коробок, роли, события аудита |
| Токен | Упрощённый ERC-721: `ownerOf`, `totalSupply`, событие `Transfer` | Уникальная коробка = уникальный токен |
| Клиент | web3.js 1.10 | Деплой, транзакции, чтение событий |
| Сети | ganache (встроенный/CLI), geth `--dev`, Sepolia | Разработка и публичная демонстрация |
| Фронтенд | HTML/CSS/JS без сборки + qrcodejs | Роли, QR на каждую коробку, верификация; GitHub Pages |

Почему web3.js, а не ethers.js: классическая официальная JS-библиотека
Ethereum — простые консольные скрипты без этапа сборки.

## Структура репозитория

```
contracts/PharmaTrack.sol   — смарт-контракт (один файл, без импортов; подходит для Remix)
scripts/
  compile.js                — компиляция: build/PharmaTrack.json + docs/abi.json
  deploy.js                 — деплой на выбранный RPC (--rpc, опционально --key)
  seed.js                   — демо-данные: участники + 3 партии с коробками
  demo.js                   — сквозной сценарий в консоли (детектор подделки включён)
  common.js                 — общие помощники (web3, ganache in-process)
test/pharmatrack.test.js    — 14 интеграционных тестов (node --test)
docs/                       — веб-интерфейс (GitHub Pages)
report/                     — отчёт и скриншоты
```

## Быстрый старт

Требуется Node.js ≥ 18.

```bash
npm install
npm run compile   # компиляция контракта
npm test          # 14 интеграционных тестов против встроенного ganache
npm run demo      # полный сценарий: выпуск коробок → продажа → детектор подделки
```

### Веб-интерфейс (рекомендуемая демонстрация)

```bash
npx ganache                                    # терминал 1
python -m http.server 8080 -d docs             # терминал 2 (или npx serve docs -l 8080)
npm run seed -- --rpc http://localhost:8545    # терминал 3: участники + демо-данные
```

Откройте <http://localhost:8080>, подключитесь по RPC `http://localhost:8545`
и введите адрес контракта (печатает `seed.js`). Аккаунты переключаются в
статус-баре: №0 — админ, №1 — производитель, №2 — дистрибьютор, №3 — аптека.
Секреты демо-коробок для проверки также печатает `seed.js`.

### Geth --dev / Remix / Sepolia

- geth: `geth --dev --http --http.api eth,web3,net --http.port 8545 console`,
  затем `npm run deploy -- --rpc http://localhost:8545`.
- Remix: файл без импортов; для ganache ставьте EVM version = paris.
- Sepolia: `npm run deploy -- --rpc <sepolia-rpc> --key <ключ>`, впишите адрес
  в `docs/config.js` — QR-коды будут вести на GitHub Pages, верификация с
  телефона пройдёт через публичный RPC без кошелька.

## API смарт-контракта

| Функция | Доступ | Назначение |
|---|---|---|
| `addParticipant(addr, role)` | Админ | Выдать роль (Manufacturer / Distributor / Pharmacy / Admin) |
| `registerBatch(name, serial, qty, expiry, instrUrl)` | Производитель | Зарегистрировать партию |
| `mintUnits(batchId, bytes32[] codeHashes)` | Производитель партии | Выпустить коробки: по токену ERC-721 на коробку (≤ 250 за транзакцию) |
| `transferCustody(batchId, to)` | Текущий custodian | Передать партию дистрибьютору/аптеке (блокируется после первой продажи) |
| `markSold(tokenId)` | Аптека-custodian | Необратимая продажа коробки: `soldAt = block.timestamp` |
| `recallBatch(batchId, reason)` | Админ или производитель | Отзыв партии в любой момент, `recalledAt` |
| `verifyView(tokenId, secret)` view | Все | Бесплатная проверка: код, статус, `soldAt`, отзыв, срок годности |
| `getBatch / getUnit / getBatchIds / getUnitIds` | Все | Чтение реестра |
| `ownerOf(tokenId)`, `totalSupply()` | Все | ERC-721-профиль: владелец коробки (custodian партии), выпуск |

События (журнал аудита): `BatchRegistered`, `UnitsMinted`, `Transfer` (ERC-721),
`CustodyTransferred`, `UnitSold`, `BatchRecalled`, `ParticipantAdded/Removed`.
